# FE Monster“遇E”无边界 3D 音乐探索场景设计

日期：2026-08-21

状态：全部视觉与交互分段已在对话中批准，等待书面复核

路径：建筑级新增子系统

## 1. 目标

在现有 FE Monster 音乐客户端中新增一个名为“遇E”的真实三维开放世界入口。它不是壁纸预览，也不是二维背景，而是可由角色自由行走、奔跑、跳跃、滑翔、攀爬和翻越的非战斗探索空间。

本设计同时满足以下目标：

1. 在现有“沙盒模式”入口旁增加“场景”按钮，进入“遇E”。
2. 建立四向持续生成、没有空气墙和地图尽头的无边界世界，并保留大量可通行空地供以后加入新内容。
3. 使用清晰、低多边形、童话卡通的真实 3D 角色；造型严格遵循已批准的原创角色图。
4. 提供走、跑、跳、滑翔、攀爬与翻越，并通过连续状态混合保证动作丝滑、不硬切。
5. 允许第一人称、第三人称和滑翔追随镜头平滑切换。
6. 在世界中的局部区域建立“音乐区”。“音乐区”不是整个世界的名字。
7. 将音乐区设为唯一固定重生锚点和空间音频主声源位置。
8. 在音乐区高处悬浮巨大场景预设卡片、现有歌单/播放控制、遇E功能坞和按需打开的设置/成就面板；面板向下俯视并持续朝向用户。
9. 场景预设卡片使用有厚度的大圆角硬玻璃框架，并实时播放预设画面。
10. 将现有歌单和播放控制 DOM 无损迁入空间界面，不复制、不截图、不重建第二套状态。
11. 提供一件非战斗拖动枪/引力工具，用于选中、移动、缩放、旋转和复位空间卡片。
12. 在外围世界加入原创的低压冒险、环境解谜和首批 10 项新成就。
13. 画面保持清晰、抗锯齿、无像素颗粒；内容与场景只允许平滑进入、退出和切换，禁止突然弹出。
14. 每个实施阶段完成后先提供可运行验收，再进入下一阶段。

## 2. 名称与范围边界

### 2.1 固定术语

- **遇E**：整个无边界三维世界的名称。
- **音乐区**：遇E中的一块固定区域，包含重生点、场景预设、歌单、播放控制、遇E功能坞、按需空间面板和空间音频主声源。
- **遇E旅人**：玩家控制的原创三维角色。
- **音翼**：角色背部的分段磨砂玻璃翼片，用于滑翔表现和移动反馈；它不是斗篷。
- **拖动枪 / 引力工具**：角色腕部工具，只能操作带空间 UI 标记的对象，没有攻击能力。
- **音乐区空间 UI**：仅指以下注册面板，不泛指整站所有 DOM：
  - 常驻的场景预设廊；
  - 由 `#orbPlaylists`、`#playlistShelf`、`.player-dock` 组成的原歌单/播放组；
  - 新建的遇E功能坞，固定含“返回音乐区、视角、引力工具、重置布局、设置、成就、退出遇E”七项；
  - 按需挂入的 `#topSearchForm`、`#searchSuggestions`、`#favoriteLibrary`、`#playlistFavoritePopover`、`#runtimeSettingsPanel` 和 `#communityProfileDialog`。
- **全局应用 UI**：窗口最小化/关闭、更新、账号登录、录制、安全确认与桌宠属于应用外壳，不进入音乐区，不纳入“所有 UI 高空悬浮”的验收范围。

### 2.2 非目标

- 不加入敌人、生命值、武器、伤害、击退、战斗任务或战斗奖励。
- 不把遇E做成固定尺寸关卡、循环地图、传送边界或带空气墙的沙盒。
- 不用二维角色贴片、预渲染人物视频或面向镜头的平面替代真实骨骼模型。
- 不把现有歌单重新画成相似 UI，不建立第二套播放器或歌单状态。
- 不用静态截图冒充实时场景预设。
- 不直接复制《光·遇》的模型、服装、发型、面具、斗篷、关卡、符号、收集物或音频资产。
- 不迁移到 Babylon.js，也不在同一页面同时维护两套完整三维引擎。
- 第一版不引入通用刚体战斗物理系统；角色和卡片使用可控的运动学系统。

## 5. 方案选择

### 5.1 采用：独立遇E运行时 + 现有 Three.js 适配器 + 混合空间 UI

- 继续沿用现有 WebGL、Three.js、GLTFLoader、AnimationMixer 和音频链。
- 在 `web/yue-e/` 建立独立运行时，不继续把完整场景逻辑堆进巨大的 `web/app.js`。
- `web/app.js` 只保留入口、播放器、成就与音频适配。
- 三维玻璃框架、阴影、碰撞和场景预设内容由 WebGL 绘制。
- 现有歌单和播放控件由 DOM 空间桥挂到三维锚点，保留真实节点和事件。
- 角色使用运动学胶囊、场景碰撞代理和已标注攀爬点，不引入战斗刚体物理。

这条路线最大化复用现有能力，同时把大型世界、角色控制、UI 空间化和音频适配隔离成可测试模块。

### 5.2 未采用：全部做成 WebGL 纹理 UI

把歌单截图或逐项重画到 Canvas 会破坏现有 DOM 事件、键盘访问、状态恢复、文本清晰度和播放控制；也不符合“直接不变无损移入场景”的要求。

### 5.3 未采用：音乐区全部面板都使用普通网页叠层

纯 DOM 叠层无法提供真实玻璃厚度、三维碰撞、空间阴影、卡片旋转和预设画面的统一深度关系，也不满足“立体清晰”的要求。

### 5.4 未采用：更换三维引擎或一次性升级全站 Three.js

现有代码、GLTF、场景预设、探针和发布链已经使用 Three.js。更换引擎或全站升级会扩大回归面，与遇E首版目标无关。遇E通过窄适配器隔离版本细节，为将来统一升级保留接口。

## 6. 模块边界

建议的新目录边界：

```text
web/yue-e/
  runtime.js                 # 生命周期和依赖注入
  yue-e.css                  # 遇E专用 DOM/UI 样式
  scene/                     # 渲染器、灯光、后处理、质量控制
  world/                     # 分块、确定性生成、原点重置、地域内容
  character/                 # 模型、运动学控制、动作图、IK、音翼
  camera/                    # 第一/第三人称和滑翔镜头
  music-zone/                # 重生点、高空 UI 锚点、聚焦布局
  spatial-ui/                # 玻璃框架、DOM 桥、命中与拖动工具
  audio/                     # 监听器、声源、环境声与后端适配
  adventure/                 # 六域活动、谜题、世界事件
  persistence/               # 布局、发现、角色与运行时快照
```

窄入口接口：

```js
window.FeYueE = {
  mount(dependencies),
  enter(options),
  exit(reason),
  snapshot(),
  restore(snapshot),
  dispose()
};
```

`dependencies` 只传现有播放器命令、歌单节点提供器、成就事件接收器、空间音频后端、资源解析器和日志接口。遇E不直接读取整个 `window` 应用状态。

## 7. 入口与生命周期

- 在 `web/index.html` 的现有“沙盒模式”入口旁放置“场景”按钮。
- 点击后先进入预载状态，音乐继续播放，不中断媒体时钟。
- 资源达到首帧安全条件后，现有页面以 420–600ms 淡出，遇E场景从模糊、低对比度逐渐变为清晰。
- 人物只有在地形、碰撞、角色模型和音乐区 UI 锚点全部 ready 且连续三帧稳定后才淡入。
- 退出时先冻结遇E输入、保存状态、恢复歌单 DOM，再淡回原页面；任何一步失败都不得遗失原 DOM 或停止播放。
- `visibilitychange`、WebGL context loss、WebView2 导航和窗口关闭都走同一个幂等清理路径。

## 8. 运行时数据流

```text
场景按钮
  → YueERuntime.enter
  → 预载音乐区核心块、角色、相机和 UI 锚点
  → 绑定播放器 / 成就 / 空间音频适配器
  → 淡入遇E并生成周围世界块

每帧输入
  → Input Router
  → Character Controller / Camera Rig / Gravity Tool
  → World Events
  → Animation Graph / Spatial UI / Audio Spatializer
  → Renderer

世界事件
  → Adventure Rules
  → Achievement Adapter
  → 现有 pixel-achievements 存储、同步和弹窗
```

播放器仍是歌曲、进度、音量和歌单的唯一权威。遇E只消费播放状态、发送现有播放器意图并空间化同一条音频流。

## 9. 无边界世界

### 9.1 地图结构

音乐区和六个首发地域构成首个手工设计簇：

| 地域 | 主体验 | 主要环境机制 |
| --- | --- | --- |
| 风弦草原 | 低空滑翔 | 草浪、风弦、上升气流、远景地标 |
| 云脊空庭 | 长距离飞行 | 云层、浮岛、连续升流、音翼能量 |
| 风暴回廊 | 天气判断 | 强风、风眼、避风石壁、声音窗口 |
| 镜雨海岸 | 路径与谜题 | 潮汐、雨水显纹、反射共鸣 |
| 雾音林地 | 听声寻路 | 浓雾、左右声像、距离衰减、隐藏洞穴 |
| 沉响峡谷 | 垂直探索 | 攀爬、翻越、声塔、回声机关、高点滑翔 |

音乐区是唯一固定重生锚点，但不是世界边界或强制中心。玩家离开任意地域后都能继续前进。

### 9.2 分块与确定性

- 世界使用二维整数块坐标和版本化种子；同一版本、同一坐标必须生成同一地形和稳定对象 ID。
- 核心音乐区与六域使用手工内容块；外围使用确定性生成块和未来内容插槽。
- 玩家移动方向的近块优先预取，侧向和后方块保持较低优先级。
- 块状态依次为 `absent → prefetch → ready-hidden → fading-in → active → fading-out → pooled`。
- 只有地形、碰撞和材质全部 ready 的块才能从远景雾中渐显，禁止整块弹出。
- 地形高度、植被密度、雾色、天空和环境声在块边界使用共享边缘采样，不能出现接缝。
- 每行进约 2km 进行世界原点重置；逻辑坐标和稳定 ID 不变，避免浮点精度抖动。
- 生成失败时延续低细节安全地形并后台重试，不能生成空气墙、不可见阻挡或强制传送。

### 9.3 留白和扩展

- 地域之间和外围长期保留大片可通行草坡、风场、云影和安静地形。
- 留白区允许低频微事件，但不得用重复收集物和任务标记填满。
- 每个生成块预留版本化内容插槽，后续可插入新岛群、遗迹、活动和地域入口。
- 新内容不能改变旧块稳定 ID 或破坏已保存的用户位置。

### 9.4 首版分块常量与高速验收

- 基础块为 256 × 256m；手工地域可以占多个基础块，但不得改变块坐标和共享边缘协议。
- 角色参数上限固定为：走 3.2m/s、跑 7.2m/s、普通滑翔 18m/s、俯冲 32m/s。超出 32m/s 的调试移动不纳入无 pop-in 验收。
- 角色周围 384m 内保持高精碰撞与近景资源，768m 内保持可见 LOD；所有方向至少预取 2 块，当前速度方向按 6 秒预测额外预取至最多 5 块。
- 大气雾从约 650m 平滑增强，在约 1100m 与远景代理融合；雾只隐藏尚未 ready 的细节，不得形成不透明墙或截断天空/远景地标。
- 世界缓存硬上限为 CPU 768MiB、GPU 512MiB；超过软阈值 80% 时按距离释放远块并复用对象池，不能通过清空近块制造闪现。
- 真实浏览器探针以 32m/s 连续前进 10 分钟并每 30 秒急转 180°，期间跨越至少三次世界原点重置；不得出现空气墙、整块弹出、可见接缝或超过一帧的输入停顿。

## 10. 画面与材质

- 世界使用原创的故事书式低多边形大形体、手绘渐变色块、柔和粗糙度和克制边缘高光。
- 主要情绪来自逆光、天光、云海、薄雾、体积光和远景褪色，不使用硬锐阴影堆砌写实感。
- 角色、地面、石体、植被、云层和玻璃必须保持清楚材质区分。
- 禁止胶片颗粒、像素噪点、抖色、马赛克过渡和低分辨率放大。
- 场景优先使用 MSAA；不支持时使用高质量后处理抗锯齿。DOM UI 始终按当前 DPR 原生渲染。
- 画质自适应时先降低远景阴影、体积光采样、反射和植被密度，再降低世界渲染比例；空间 UI 和人物轮廓不可先降清晰度。
- 预览或资源替换只有在新内容 ready 后才交叉淡化，不能先清空再突然显示。

## 11. 遇E旅人与动画

### 11.1 资产

- 三张批准图是视觉概念锚点，不冒充可直接运行的模型。第一项资产闸门先交付正/侧/背三视比例板、材质色板、骨骼命名表，以及不含完整动作集的外观/骨骼基准 `yue-e-traveler-lookdev.glb` 360° 中性光转台；用户批准该转台后才能进入动作制作。
- 第 2 阶段在同一批准源模型上加入走跑跳基础片段；第 3 阶段补齐完整动作集并输出最终运行资产 `web/assets/yue-e/character/yue-e-traveler.glb`。最终资产使用米制、`+Y` 向上、角色前方 `-Z`、双脚中点为原点，静止总高约 1.35m。
- 使用单一原创骨骼模型，不以多个外观相近模型拼接状态；模型必须有实际体积、灯光响应、阴影、骨骼蒙皮和运动学碰撞胶囊。
- 近景 LOD0 目标 35k–60k 三角形、蒙皮骨骼不超过 96、单顶点影响不超过 4；另提供约 50% 与 20% 三角形的 LOD1/LOD2，三档轮廓不能突然改变。
- 基础色/遮罩贴图最长边不超过 2048px；不使用照片皮肤、毛孔、真实发丝或颗粒法线。面罩、头发、衣服、音翼、胸口光核和腕部工具使用独立材质槽或可控材质实例。
- 音翼左右各六个圆角分段，折叠和展开由同一骨骼/节点结构驱动。
- 肩、肘、腕、髋、膝、踝和手脚必须清楚可分，服装不得遮死动作关节。
- GLB 内至少包含 `idle`、`walk`、`run`、`start`、`stop`、`turn_l`、`turn_r`、`jump_start`、`air`、`land_soft`、`land_heavy`、`hover`、`glide`、`dive`、`climb_idle`、`climb_up`、`climb_side`、`mantle` 和 `wing_fold`/`wing_open` 命名片段；导入检查拒绝缺片段、重复骨骼名、负缩放和未绑定网格。
- 角色阶段的视觉验收使用批准概念图并排对照正面、侧面、背面、俯视和动作慢放；重点比较头身比、面罩留白、发型块面、衣裤轮廓、胸口光核、腕部工具与十二片音翼。任何明显偏差必须回到资产阶段修正，不能用镜头或辉光掩盖。

### 11.2 运动学能力

- 地面：待机、走、跑、启动、停止、转向和小步修正。
- 跳跃：预备压身、起跳、空中循环、短落地、重落地和恢复。
- 空中：悬停、滑翔、俯冲、爬升、侧倾和落地收翼；普通滑翔不设耗尽倒计时，升空推进使用最多三格音翼能量，落地、稳定上升气流和音乐区会连续补充。
- 攀爬：三点接触、上下左右移动、体力/可攀高度规则和取消；满体力支持约 8 秒持续向上攀爬，停在有效支点时以两倍速度恢复，耗尽后平滑下滑到最近安全支点，不触发伤害或死亡。
- 翻越：探测边缘、手掌支撑、抬膝、重心越过、站立恢复。
- 角色没有攻击、受击、死亡或战斗锁定状态。

### 11.3 动画图

- 走跑由二维 Blend Tree 根据局部速度和转向角连续混合。
- 走跑过渡约 0.18s，起跳过渡约 0.12s，落地恢复约 0.22s，滑翔展开约 0.28s。
- 动画更新使用实际 `dt`，与渲染帧率解耦；不得通过固定帧数计时。
- 脚底 IK 防止滑步和斜坡悬空；攀爬手脚 IK 锁定已验证接触点。
- 音翼和衣摆使用二级跟随或轻量骨骼动力学，不能抖动、穿身或迟滞过大。
- 根运动只用于翻越等已标注片段；普通移动由运动学控制器主导，防止动画与碰撞位置分离。
- 全部必需动作在人物出现前预载；状态首次触发不得临时卡顿。

## 12. 相机

### 12.1 第三人称

- 默认 FOV 50°，距离约 3.4m，略高于角色肩部。
- 跑动时用阻尼拉至约 4.2m；停止后缓慢恢复。
- 使用相机碰撞球从角色头部向期望位置扫掠，遇墙靠近，离墙后渐回，不能穿模或抽动。
- 镜头跟随重心而不是逐帧追骨骼，角色转身和落地不会造成剧烈抖动。

### 12.2 第一人称

- 默认 FOV 78°，近裁剪面约 0.05m。
- 只在本机第一人称渲染层隐藏头部和头发；双臂、右腕引力工具、世界层完整模型、第三人称模型和身体阴影保持存在。本规格不引入多人角色系统。
- 第一人称和第三人称共用同一准星命中射线和交互目标。

### 12.3 滑翔追随

- 默认 FOV 62°，起飞后约 0.28s 拉远至 5.2m。
- 俯冲时增加地形前瞻，转弯只做轻微侧倾，降落前降低镜头延迟。
- 镜头服务地形判断和风景，不加入战斗锁定或目标追踪。

### 12.4 切换

- `V` 键在第一和第三人称间切换；滑翔状态自动使用滑翔追随，着陆后回到用户上一次地面模式。
- 切换约 0.42s，依次锁定准星目标、沿阻尼样条移动、渐隐/渐显头部、收稳 FOV 和景深。
- 切换中角色、拖动枪和歌曲播放不冻结。
- 设置提供 FOV、灵敏度、反转和镜头晃动强度；镜头晃动可完全关闭。

## 13. 音乐区

### 13.1 空间布局

- 音乐区中央为开阔活动地面，放置唯一固定重生点和空间音频主声源。
- 场景预设在用户左前上方弧形排列；现有歌单和播放控制在右前上方；遇E功能坞位于右侧外缘；搜索/收藏、设置和成就面板仅在打开时占用预留的中央外侧高空锚点。
- 所有面板高度约 6–10m，不接触地面；中央移动、重生和世界出口保持无障碍。
- 单张预设基准尺寸约 3.6 × 5.2m；歌单主面板约 7.5 × 5.4m；功能坞约 6.4 × 1.8m；搜索/收藏、设置和成就等按需面板不小于 4 × 3m。
- 面板默认向下俯视约 45°，水平 Yaw 用阻尼持续转向用户。
- 用户绕到侧面或背后时，面板约 0.35s 缓慢转向；内容从不翻面或镜像显示。

### 13.2 进入表现

- 场景地形先从雾中显现，随后重生环、预设框、歌单/播放组和功能坞分批淡入。
- 玻璃先出现轮廓和厚度，内容只有在第一帧 ready 后才交叉淡入。
- 多张卡片允许 40–70ms 轻微错峰，但总过程不得表现成逐张突然弹出。

### 13.3 预设聚焦

- 短点击预设后，未选中预设在 180–260ms 内渐隐并停止接收命中。
- 选中卡片使用约 0.48s 阻尼移动和缩放，移至用户前上方中心并放大约 1.35×。
- 聚焦卡片最低仍保持约 5.8m 高度，继续向下对准用户。
- 退出聚焦后按保存的高空布局平滑恢复，预览 ready 后再淡入其他卡片。
- 第一、第三人称均可观看和操作聚焦卡片。

## 14. 混合空间 UI

### 14.1 明确的三层合成

CSS 3D DOM 与 WebGL 不共享深度缓冲，因此本设计不假装做不存在的逐像素混合，而使用同一相机驱动的三层合成：

1. **世界 WebGL 层**：绘制世界、人物、玻璃背壳/侧壁、投影和每张面板的命中代理。
2. **CSS 3D DOM 层**：只在框架“内容开口”内显示真实 DOM；每个开口用投影后的四边形 `clip-path` 裁切，层本身不绘制玻璃。
3. **透明 WebGL 前景层**：用同一视图/投影矩阵绘制正面倒角、边缘高光、柔光和准星，始终盖住 DOM 开口边缘。

空间 UI 按用户要求属于“始终可读”的世界锚定界面，不参与世界建筑的逐像素遮挡；它只在位于相机后方或完全离开视锥时隐藏。音乐区布景需保留从活动地面到高空面板的无遮挡视廊。玻璃背壳仍在世界层接收光照、阴影和侧视透视，前景层只补正面边缘，避免把整张卡片做成平面叠层。

三层共享单一 `SpatialPanelPose`、相机矩阵、DPR 和投影计算。每帧先更新世界与面板姿态，再写 DOM 变换，最后绘制前景层；相机急转、系统缩放和卡片拖动时三层边缘误差不得超过 1.5 CSS px。

### 14.2 三维玻璃框架

- 每张卡片使用真实三维网格，包含厚度、大圆角、倒角、边缘高光、透明/折射近似、阴影和命中体。
- 框架保持硬玻璃感，不使用一张半透明 CSS 矩形冒充三维物体。
- 悬停时边缘和附近空气产生克制的青色/琥珀柔光；内容亮度不得被光晕淹没。
- 玻璃边框拥有约 32px 等效交互带，用于区分“操作 UI 内容”和“拖动整个框架”。

### 14.3 场景预设适配契约与容量

首版注册表必须覆盖现有 11 个内置预设 `lyric`、`wallpaper`、`cube`、`free-cubes`、`void-prism`、`topography`、`soundscape-workshop`、`chladni`、`rain-glass`、`cover-particles`、`book`，并通过通用沙盒适配器覆盖用户保存的场景预设。缺少实时适配器的预设不能用截图顶替，也不能把第 4 阶段标记为完成。

每个适配器实现同一受控接口：

```js
{
  id,
  prepare({ assets, renderer }),
  render({ target, width, height, time, dt, audioFrame, quality }),
  suspend(),
  resume(),
  dispose()
}
```

- `render` 只能写入传入的 `WebGLRenderTarget` 或受控同源画布，不得切换主页面、改写播放器状态或读取任意全局 DOM。
- 预设使用同一份只读 `audioFrame` 和时间快照，不复制歌曲、播放进度或用户配置；预览实例自身的粒子/相机状态与正式播放状态隔离。
- 所有卡片都存在于高空扩展弧廊；布局保证任一可读视锥窗口最多出现 6 张内容面。窗口外卡片保留玻璃轮廓和最后合法帧，但位于不可读视角；卡片进入可读窗口时，实时帧 ready 后才淡入内容。
- Preview Scheduler 复用最多 6 个实时目标。聚焦/悬停卡片按显示器 rAF 更新，其他可读卡片在参考硬件上不低于 24fps；每个显示帧的预览 GPU 预算为 4ms，超预算时先降低预览内部特效与目标分辨率，不突然停止或跳帧显隐。
- 普通卡片目标从 720 × 1024 起步，悬停最高 900 × 1280，聚焦最高 1200 × 1706；根据实际屏幕面积降采样，但内容像素密度不得低于 1 CSS px 对 1 输出像素。
- 渲染目标池（含颜色、深度和双缓冲过渡）显存预算不超过 128MiB；不可读预设暂停并释放临时目标。
- 聚焦升分辨率、新适配器 ready、窗口切换和失败恢复都使用双目标交叉淡化，不能把低分辨率纹理直接拉大或先清空。

### 14.4 现有 DOM 无损迁移

进入遇E时，DOM 桥移动而不是克隆第 2.1 节列出的真实节点。`#orbPlaylists`、`#playlistShelf` 和 `.player-dock` 常驻在歌单/播放组；搜索/收藏、设置和社区资料/成就节点按需进入预留空间锚点，关闭后回到已记录的原位置。

规则：

- 迁移前记录父节点、下一兄弟节点、hidden/inert/ARIA、焦点、滚动位置、表单选择区间和打开的 popover/dialog 状态。
- 真实节点挂到 `yue-e-spatial-dom-layer` 的对应空间锚点，原事件监听器、ID、媒体状态和可访问性保持不变。
- DOM 层每帧根据三维锚点生成 CSS 3D 变换；文字按当前 DPR 原生栅格化，并严格裁在内容开口内。
- 点击内容区继续调用原有按钮、滚动、输入、选择和播放逻辑。
- 退出或发生异常时按原顺序恢复真实节点和状态，操作必须幂等。
- 不允许同时存在原节点和克隆节点，避免重复 ID、重复事件和双重播放。

### 14.5 Pointer Lock 与 UI 输入状态机

| 状态 | 鼠标/键盘所有权 | 进入 | 退出 |
| --- | --- | --- | --- |
| `navigate` | pointer lock；角色和相机接收移动；DOM `pointer-events:none` | 场景 ready 或从 UI 返回 | 准星对准 DOM 内容后按 `E`，或瞄准边框开始拖动 |
| `ui-interact` | 释放 pointer lock；角色移动冻结；真实 DOM 接收鼠标、滚轮、输入和选择 | 从 `navigate` 按 `E` | 再按 `E` 或 `Esc`；恢复原焦点并请求 pointer lock |
| `card-manipulate` | pointer lock；引力工具独占指针增量；DOM 不接收事件 | 命中边框并满足长按/旋转手势 | 释放、`Esc` 取消或失去目标 |
| `spatial-modal` | 与 `ui-interact` 相同，同时对背景面板设置 `inert` | 打开设置或社区资料/成就 | 关闭按钮或 `Esc`，回到先前状态 |

- `Esc` 的优先级固定为：取消当前卡片变化 → 关闭最上层 popover/dialog → 离开 UI 操作 → 释放 pointer lock/打开场景暂停层。
- 进入 `ui-interact` 不把第一次按键伪装成 DOM 点击；光标在释放后出现，用户随后直接操作真实控件。
- 若浏览器拒绝自动重新锁定指针，显示居中“单击继续探索”层；歌曲、动画淡入和 DOM 状态不重置。
- pointer lock 丢失、窗口失焦和场景退出都必须清理拖动状态、恢复焦点与 `inert`，不能留下不可点击的原页面。

## 15. 拖动枪 / 引力工具

### 15.1 命中范围

- 射线只命中带 `spatial-ui-manipulable` 标记的卡片框架。
- 对角色、动物、地形、建筑、冒险机关和普通 DOM 内容无伤害、无移动、无击退。
- 命中边框时工具接管；命中内容区域时保持原 UI 点击行为。

### 15.2 操作

| 输入 | 行为 |
| --- | --- |
| 准星靠近 | 约 80ms 柔光高亮 |
| 左键短点击 | 聚焦/打开预设 |
| 左键按住超过 120ms | 抓取卡片 |
| 抓取时移动鼠标 | 沿相机视平面移动 X/Y |
| `Alt` + 拖动 | 调整远近深度 |
| 抓取时滚轮 | 在 0.65×–2.25× 之间连续缩放 |
| 右键拖动 | 在可读范围内旋转 |
| `R` | 0.35s 平滑恢复默认锚点 |
| `Esc` | 取消本次变化，恢复抓取前变换 |

### 15.3 手感和安全

- 抓取、移动、缩放、旋转和释放使用与帧率无关的临界阻尼，不直接把卡片位置硬设为鼠标位置。
- 释放约 0.22s 停稳；不得弹飞、持续漂移或突然吸附。
- 面板不能进入人物 2.5m 安全半径，也不能遮挡重生点、出口和主要冒险路线。
- 保存每张卡片的位置、旋转和比例；提供音乐区布局一键复位。
- 卡片移动或缩放时保持实时内容和清晰度，不切换成模糊占位图。

## 16. 空间音频

### 16.1 所有权和后端

- 现有播放器继续产生唯一歌曲流。
- `YueEAudioAdapter` 只把同一音频流路由到现有 Web Audio Panner、XAudio2/X3DAudio 或可用的原生空间后端。
- 不创建第二个媒体元素、不重复解码、不复制播放进度。
- 原生后端不可用时回退 Web Audio；再不可用时回退普通立体声，歌曲不能中断。

### 16.2 监听器和声源

- 声源位置固定在音乐区重生环中心。
- 监听器位置取角色头部，监听器朝向取当前相机，避免第三人称镜头拉远改变听感距离。
- 音乐区近场保持完整音乐和轻量空间反射；离开后逐步增加方向感、距离衰减、遮挡低通和地域环境声。
- 远距离仍保留低电平歌曲底层，默认不让歌曲完全消失；环境声在其上平滑交叉淡化。
- 返回音乐区时按同一曲线恢复，不发生音量跳变、相位突变或重复起播。
- 空间音频计算以实际 `dt` 和连续参数斜坡更新，不逐帧硬切后端参数。

## 17. 非战斗冒险

核心循环：

```text
远景吸引 → 自由选路 → 移动挑战 → 理解环境 → 抵达奇观 → 成就记录
```

规则：

- 没有生命值、敌人、战斗和时间压力。
- 跌落只返回最近安全落脚点，不扣资源、不清除成就进度、不打断歌曲。
- 玩家随时可以使用明确的返回动作回到音乐区。
- 引导优先使用日光、云缝、高大轮廓、风、空间声音和环境运动；HUD 箭头只在用户持续迷失时轻量出现。
- 六域体验按第 9.1 节执行；每个地域至少包含一条易到达主路、一条可选支路、一个远景奇观和一个非重复环境机制。
- 空白地形不以收集物密度衡量完成度。

### 18.2 判定边界

- “旅程”在角色从音乐区半径 60m 的外边界向外跨出时开始；返回音乐区、主动退出遇E、页面重载或使用返回动作时结束。暂停、切到后台后恢复不会另开旅程，但暂停期间不累计时间或距离。
- `初遇E` 在首次产生合法旅程时解锁。
- `无界行者` 只累计同一旅程中运动学控制器产生的有效路径长度；传送、原点重置、纠错位移、卡顿恢复和单帧超过速度上限的位移不计，达到 10,000m 解锁。
- `六域回声` 记录稳定地域 ID `wind-string-meadow`、`cloud-ridge-court`、`storm-corridor`、`mirror-rain-coast`、`mist-sound-wood`、`deep-echo-canyon` 的地标集合；重复进入不重复计数，六项齐全解锁。
- `借风而行` 要求连续 90 秒保持 `glide`/`dive` 且未接地、攀附、传送或返回；正常暂停冻结计时，context loss 或恢复到安全点会重置本次连续计时。
- `云脊之上` 从云脊入口检查点开始，到最高平台触发器结束；使用返回音乐区、调试传送、辅助跳过或崩溃恢复均使本次尝试失效，普通落地和改路不失效。
- `风暴读者` 必须按当前天气周期正确通过三个有序风向窗口；走错只重置本地三段序列，不影响地域完成。
- `镜雨共振` 要求四个稳定节点在同一个 3 秒共振窗口内处于发声状态；暂停冻结窗口。
- `雾中听路` 只在用户主动开启“听路挑战”后判定；完成迷雾段前使用可视路线提示或辅助跳过会结束本次成就尝试，但不会阻止通关，也不禁用字幕、音量平衡或听力辅助设置。
- `峡谷攀响` 要求在同一峡谷路线会话中依次产生有效攀爬、翻越和从标记高点进入滑翔三个事件；回到路线入口或使用跳过才重置。
- `随歌远行` 要求同一稳定曲目 ID 在同一遇E会话内覆盖至少 95% 的唯一播放时间，并在该曲目期间进入三个不同环境声区。暂停和向后回听允许，重复时间不重复累计；向前 seek 超过 2 秒、换歌或退出场景会重置本次曲目尝试。

### 18.3 事件与现有 API

`YueEAchievementAdapter` 只接受以下白名单结构，并把进度映射到现有 `window.feAchievements.setProgress(id, value)`，完成时调用 `unlock(id)`：

```json
{
  "eventId": "session-id:monotonic-sequence",
  "achievementId": "yue-e-first-arrival",
  "value": 1,
  "regionId": "wind-string-meadow",
  "journeyId": "opaque-session-local-id",
  "sessionId": "opaque-runtime-id",
  "timestamp": 0
}
```

适配器拒绝未知 ID、负数/非有限数、超长字符串、未来时间戳和重复 `eventId`；payload 不包含自由 HTML、本地路径或命令名称。集合型和连续型条件先由遇E规则器归一化为单调进度，再交给现有系统，保证重复事件、保存恢复和账户合并都不会重复解锁。

## 19. 状态与持久化

版本化快照至少包含：

```json
{
  "version": 2,
  "durable": {
    "cameraMode": "third-person",
    "world": {
      "seedVersion": 1,
      "visitedRegions": [],
      "discoveredLandmarks": []
    },
    "musicZone": {
      "panelTransforms": {},
      "focusedPresetId": null
    },
    "accessibility": {
      "cameraShake": 0.15,
      "fovFirstPerson": 78,
      "fovThirdPerson": 50
    }
  },
  "volatileRecovery": {
    "runtimeId": "same-live-runtime-only",
    "logicalPosition": [0, 0, 0],
    "logicalRotation": 0,
    "movementMode": "ground",
    "capturedAt": 0
  }
}
```

- **正常进入、退出后重进、页面重载和应用重启**一律在音乐区固定重生环出现；持久状态不得把上次世界坐标当作下次出生点。
- `volatileRecovery` 只存在于同一个仍存活的 `YueERuntime` 内，用于 WebGL context loss 或渲染器重建；仅当 `runtimeId` 相同、捕获时间不超过 10 秒且目标块碰撞 ready 时恢复逻辑坐标，否则回音乐区。
- 系统每 0.5 秒在“站立稳定、无遮挡、非移动平台”的位置更新内存中的最近安全落脚点。跌落返回该点叫“安全回退”，不是重生；没有合法安全点时才回音乐区。
- 用户长按 `T` 1.2 秒执行“返回音乐区”；这与跌落回退、context 恢复和正常进入的语义分离。
- 恢复数据保存逻辑世界坐标，不保存原点重置后的临时局部坐标。
- 面板变换按稳定 UI ID 保存并做尺寸/距离校验。
- 快照损坏时只重置遇E状态，不影响播放器、歌单、账户或其他场景。
- 旧版本迁移必须是显式纯函数；无法迁移时保留损坏证据并使用安全默认值。
- 歌曲进度和歌单不进入遇E快照，继续由原播放器负责。

## 20. 故障与恢复

- **WebGL 不可用**：场景按钮显示不可用原因和重试，不让主应用崩溃。
- **角色或核心音乐区资产失败**：不进入场景；保留当前页面和播放，提供重试。不得用不符合批准造型的替代人物冒充完成。
- **外围块失败**：显示连续低细节安全地形并后台重试，不生成墙或断崖边界。
- **预设预览失败**：保留最后一个合法帧并显示克制 loading 状态；恢复后交叉淡化到实时画面。
- **DOM 迁移失败**：立即执行幂等恢复，原歌单和播放栏必须回到原父节点。
- **WebGL context lost**：冻结输入、保留快照、显示恢复层；重建完成后从雾中淡回，不能闪白或整场突然出现。
- **空间音频失败**：按“原生空间 → Web Audio → 立体声”降级，歌曲持续播放并显示可解释状态。
- **内存压力**：先释放远块、不可读预设目标、远景效果和非交互装饰；参考硬件上的可读预设仍保持第 14.3 节的帧率下限，最后才降低世界渲染比例，DOM 与角色清晰度优先。
- **退出中断**：再次调用 `exit()` 必须安全完成剩余清理，不能重复注册事件或遗留 pointer lock。

## 21. 性能与清晰度预算

首要验收环境为 Windows 11、当前稳定 Chromium/WebView2、1920×1080、60Hz、16GB RAM、6 核/12 线程级 CPU（Intel i5-12400 / Ryzen 5 5600 或更高）和 6GB 独显（RTX 3060 / RX 6600 或更高）。不同硬件另记录质量档，不把低端降级结果冒充主验收结果。

- 目标 60 FPS；10 分钟稳态探针的中位帧时间不高于 16.6ms、P95 不高于 20ms，单次资源准备造成的主线程长任务不得超过 50ms。视觉循环使用 `requestAnimationFrame` 和真实 `dt`，不设置固定 FPS gate。
- 稳态主线程目标低于 12ms，主相机 GPU 帧与预览调度合计目标低于 16.6ms；偶发资源准备不得阻塞连续输入。
- 音乐区主相机通道 draw calls 目标不高于 450，预览调度每显示帧等效不高于 200，合计不高于 650；视锥内主世界三角形目标不高于约 1.5M。两类 draw calls 分开上报，不能把预览通道藏在统计外。
- 同屏只保留一个主角色的完整蒙皮和必要交互物体；远景植被使用实例化和 LOD。
- 近块、角色、UI 和交互碰撞分优先队列；远块准备使用有界时间片。
- 世界渲染比例默认按 DPR 上限控制，不低于 0.85；不足时先降体积光、阴影、反射和植被。
- DOM 空间 UI 保持当前 DPR；预设渲染目标按屏幕占用面积动态分配，并以交叉淡化切换分辨率。
- 遇E运行时（世界、人物、预览目标和缓存）额外常驻内存目标不高于 1.5GiB；退出后除共享缓存外必须释放，连续进入/退出 10 次不得单调增长超过 5%。
- 禁止胶片颗粒、低分辨率噪声、突发 shader 编译和首用动作加载卡顿。
- 进入场景前预热核心 shader、角色动作、玻璃材质和首屏预设。

## 22. 可访问性与输入

默认键鼠映射如下；所有映射都有设置项、冲突检查和恢复默认值：

| 输入 | 默认行为 |
| --- | --- |
| `W/A/S/D` | 相对相机移动；攀爬时改为沿表面移动 |
| `Shift` | 按住跑动 |
| `Space` | 地面按下跳跃；空中按住超过 180ms 展开音翼进入滑翔；滑翔中再次短按消耗一格能量推进 |
| `Ctrl` | 滑翔下降；攀爬时松手下落到安全状态 |
| `E` | 上下文交互、进入/离开 DOM 操作模式、附着可攀表面 |

- 成就和交互反馈同时提供视觉和非刺耳声音提示，不只依赖颜色。
- 低性能模式不移除玩法、碰撞、成就或歌单功能，只降低装饰效果。

## 24. 分阶段验收顺序

实现计划必须按以下阶段推进；每阶段完成后停止并让用户验收：

1. **角色外观/骨骼闸门与运行时壳**：三视比例板、材质色板、骨骼命名和不含完整动作集的 `yue-e-traveler-lookdev.glb` 360° 转台；通过后再接“场景”按钮、进入/退出、空音乐区、稳定帧和错误回退。外观/骨骼转台不通过就不进入动作制作。
2. **风险垂直切片**：在已批准的外观/骨骼源模型上加入走跑跳基础片段和第三人称；只接一块风弦草原、一个 `lyric` 实时预设、`#orbPlaylists` 一个真实 DOM 面板和 Web Audio 音乐区声源。该阶段必须同时证明三层合成、DOM 输入状态、预设适配、基础分块和音频不重播；未通过前不扩展六域与全预设。
3. **完整移动、最终运行 GLB 与镜头**：补齐第 11.1 节全部命名片段并输出最终 `yue-e-traveler.glb`，完成滑翔、音翼能量、攀爬、翻越、IK、第一/第三人称和滑翔追随镜头。
4. **完整音乐区空间 UI**：11 个内置及用户沙盒预设适配、最多 6 个并发实时目标、完整原歌单/播放组、功能坞、按需设置/成就面板和聚焦行为。
5. **拖动枪**：选中高亮、移动、缩放、旋转、安全范围和持久化。
6. **无边界世界**：256m 分块、原点重置、六域、留白地形、32m/s 预取和无 pop-in。
7. **完整空间音频与冒险**：原生/Web Audio 降级、六域环境声、六域非战斗玩法和安全回退。
8. **成就与最终质量**：10 项成就目录/挂饰/判定、跨会话状态、参考硬件性能、清晰度和完整回归。

任何阶段未通过，不提前把后续阶段视为完成，也不以静态图片替代该阶段要求的真实三维或交互验收。

## 25. 完成定义

只有同时满足以下条件，遇E首版才算完成：

- 用户能从沙盒模式旁进入和退出遇E，播放器状态不中断。
- 世界在任意方向持续生成，实际游玩中不存在边界、回弹和强制传送。
- 角色严格匹配批准图并以真实三维骨骼模型运行。
- 走、跑、跳、滑翔、攀爬、翻越和镜头切换都连续流畅。
- 音乐区是局部区域、唯一固定重生点和空间音频主声源。
- 第 2.1 节注册的音乐区空间 UI 全部高空、巨大、向下约 45° 并持续面向用户；全局应用 UI 维持应用外壳职责。
- 场景预设实时播放；点击后其余隐藏，选中卡片平滑居中放大。
- 原歌单和播放控制以同一 DOM 节点无损工作并可安全恢复。
- 拖动枪可以移动、缩放和旋转卡片，但不能作用于人物和世界。
- 六域提供非战斗冒险，10 项成就由现有系统可靠记录。
- 画面清晰、无像素颗粒、无突然出现，性能与回归探针通过。
- 八个实施阶段均已分别向用户展示并获得验收。
