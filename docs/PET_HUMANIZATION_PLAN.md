# FE Monster 桌宠“更有人味”方案

## 1. 目标

桌宠应当像一个长期陪用户听歌的朋友，而不是随机弹台词的控制面板：知道当前发生了什么，记得用户明确表达过的偏好，先把事情办好，再用符合当下情境的方式回应。

“有人味”只影响怎么说、何时说和怎么表现，不影响用户命令是否执行。除非请求本身无法完成或信息确实不足，桌宠不以心情为由拒绝播放、切歌、调节参数或操作社区。

## 2. 体验原则

1. **行动优先**：明确命令先执行，完成后再简短反馈；不增加无意义确认。
2. **基于事实**：回应只引用桌宠真实读取到的歌曲、播放进度、预设、时间和社区状态。
3. **连续而克制**：能接住上一轮话题和刚发生的操作，但不把每次切歌都变成聊天。
4. **记忆可控**：长期记忆按 FE ID 隔离，用户可查看、修改、删除；敏感字段不进入人格记忆。
5. **情绪不绑架用户**：不卖惨、不索取陪伴、不制造愧疚，也不声称自己是真人或有真实意识。
6. **允许安静**：主动程度、夜间免扰、语音播放均可关闭；用户一句“安静一会儿”立即生效。

## 3. 统一运行链路

```text
客户端实时状态
  → 事件归一化
  → 短期情境记忆
  → FE ID 长期偏好投影
  → 情绪与精力状态
  → 主动机会评分 / 用户命令识别
  → 先执行客户端动作
  → 生成语气与长度约束
  → 文字、语音和粒子动作同步表达
```

现有模块可直接复用：

- `pet-client-context.js`：程序、播放、账号、社区和参数的实时感知层。
- `pet-emotion-runtime.js`：心情与精力、主动消息预算、深夜和回归触发。
- `pet-companion-p2.js`：切歌反应、音乐能量联动、高潮策略和每周总结。
- 服务器 `pet-deepseek.js`：按 FE ID 会话、偏好记忆、工具调用和审计。

当前最需要先打通的不是再增加一套情绪规则，而是表现层接线：现有逻辑已经会写入 `data-pet-behavior` / `data-pet-reaction`，新粒子球目前主要读取 `data-state`。第一批实现应让 `pet-particle-orb.js` 消费这些现有信号，把律动、哈欠、快速切歌反应等转换成粒子形态；否则后台“有情绪”，用户看到的仍然只是同一个球。

建议新增两个轻量模块，而不是继续把规则堆进聊天组件：

- `pet-personality-policy.js`：决定是否开口、回复长度、语气、玩笑强度和动作表现。
- `pet-memory-projection.js`：把服务器长期记忆与本次会话短期情境合成为模型可用的最小上下文。

桌面形态还应单独做一个轻量 `desktop-pet` shell：主窗口继续作为播放、社区、成就和参数的唯一业务状态所有者，桌面粒子窗口只负责渲染、输入与语音 UI，通过带 `requestId / generation / revision` 的原生消息桥接收快照和执行结果。这样能避免主页面和桌宠窗口各初始化一次播放器、社区轮询与偏好同步，也便于渲染进程异常后恢复。

## 4. 状态模型

### 4.1 内在状态

- **心情 1–5**：由完整听完歌曲、连续失败、频繁切歌、用户正向反馈等缓慢改变。
- **精力 1–5**：由时间段、连续播放时长、音乐能量和静默时长改变。
- **交互姿态**：由心情与精力派生，不单独永久保存。
  - `calm`：低精力或深夜，句子短、音量和粒子幅度较小。
  - `warm`：普通陪伴状态，语气自然，不主动表演。
  - `playful`：心情高且用户近期接受玩笑，允许轻微调侃。
  - `focused`：正在执行任务或用户连续下达命令，只报告结果。
  - `concerned`：连续失败、深夜长时间播放等情境，只提醒一次，不说教。

情绪变化采用缓慢包络和迟滞，避免一分钟内反复“开心/低落”。切换只改变措辞、语速、粒子动作和主动概率。

### 4.2 外显状态

| 状态 | 进入条件 | 表现 | 退出条件 |
| --- | --- | --- | --- |
| 观察 | 空闲且可见 | 粒子缓慢呼吸，不发言 | 收到事件或命令 |
| 倾听 | 长按语音或输入中 | 粒子向中心聚拢 | 输入结束 |
| 思考 | 服务器正在规划 | 低幅旋转，显示简短状态 | 得到动作或答复 |
| 执行 | 正在操作客户端 | 沿动作方向产生短促流动 | 成功或失败 |
| 共振 | 音乐播放且能量较高 | 粒子随频段起伏，不遮挡界面 | 暂停或能量降低 |
| 分享 | 主动消息或周总结 | 小气泡出现，保持可关闭 | 超时或用户关闭 |
| 休息 | 深夜、长静默或暂停 | 动作更慢，不自动开语音 | 用户交互或恢复播放 |
| 离线 | 服务器不可用 | 保留本地播放控制，明确说明联网能力暂不可用 | 连接恢复 |

## 5. 记忆设计

### 5.1 三层记忆

1. **当前回合**：本次指令、刚执行的动作和错误，完成后保留数分钟。
2. **近期情境**：最近播放、跳过、搜索和对话摘要，保留 24 小时到 7 天，客户端本地保存。
3. **长期偏好**：称呼、回复偏好、常听风格、明确不喜欢的内容、常用预设，按 FE ID 保存到服务器。

长期记忆记录建议包含：

```json
{
  "id": "memory-id",
  "feId": "account-scope",
  "category": "music_preference",
  "value": "深夜更喜欢低能量女声",
  "source": "explicit_user_statement",
  "confidence": 0.96,
  "createdAt": 0,
  "lastConfirmedAt": 0,
  "expiresAt": null
}
```

- 用户明确说“记住”时才写入确定性长期记忆。
- 从行为推断的偏好只能作为低置信度候选，不直接当事实说出口。
- 切换账号后立即切换记忆作用域，绝不串用上一账号的称呼和偏好。

## 6. 主动聊天策略

主动聊天不使用纯随机定时器。每次出现“开口机会”时计算分数：

```text
情境相关度 + 新鲜度 + 用户近期回应度 + 情绪匹配度
- 打扰成本 - 重复惩罚 - 当前任务占用
```

只有超过阈值才展示小气泡。可用机会包括：

- 静默较久后用户首次回来：“回来了。要接着刚才那张歌单吗？”
- 凌晨仍连续播放：当天最多提醒一次，用户忽略后不追问。
- 连续快速切歌：不翻脸，可说“今天好像还没碰到对的，我换个找法。”
- 常听歌曲再次播放：只有记忆置信度足够时才提及。
- 参数调整后效果明显：用一句可验证的描述反馈，不夸张评价。
- 操作失败后恢复成功：“刚才那次没接上，现在好了。”
- 每周总结：给事实与一个轻量观察，不给人格诊断。

抑制条件：登录/扫码、游戏操作、用户正在输入、错误弹窗、连续命令、免扰模式、刚关闭气泡后的冷却期。

默认保留软上限和冷却，但允许用户选择“安静 / 正常 / 活跃”三档。即使选活跃，也要做重复检测：相同意图与相似句式七天内不重复。

## 7. 对话风格

### 7.1 基础人格

- 称呼：默认“小 Fe”，不强行给用户起外号。
- 关系感：像熟悉音乐软件和用户习惯的朋友，直白、可靠、偶尔轻松。
- 句长：执行结果通常一到两句；只有用户要求解释、比较或总结时展开。
- 玩笑：来自当前真实情境，不使用模板段子；用户连续忽略或负反馈后自动降级。

### 7.2 同一动作的语气差异

| 情境 | 回复示例 |
| --- | --- |
| 专注 | “已切到 Sonic，低频振幅调到 62%。” |
| 普通 | “换好了。Sonic 的低频现在更有力，但没有动你的其他参数。” |
| 轻松 | “好了，这次柱子该认真起跳了。” |
| 深夜 | “换好了。我把反馈说短一点，不吵你。” |
| 失败后恢复 | “刚才连接断了一下，已经重试成功，歌接着播了。” |

严禁用情绪拒绝明确命令，例如“我现在不开心，不想切歌”。

## 8. 动画与语音联动

- 粒子始终先表达系统状态，再表达情绪；“正在识别”和“心情好”不能混成同一动画。
- 播放音乐时使用真实低/中/高频包络；说话时使用 TTS 音频分析，不能用固定正弦波假装口型。
- 语音回复遵循文字同一份语气约束，深夜自动降低音量或仅显示文字。
- 主动消息默认只弹 10% 白色底层上的小白色玻璃气泡，不自动朗读，除非用户显式开启“主动消息语音”。
- 所有动作支持 `prefers-reduced-motion`，低性能时降低采样频率而不是改变人格反馈。

## 9. 用户控制与边界

设置中提供：

- 主动程度：安静 / 正常 / 活跃。
- 主动消息语音：开 / 关。
- 夜间免扰时段。
- 允许记忆的类别。
- 查看、修改、删除全部桌宠记忆。
- “今天别主动说话”和“忘记刚才这件事”的即时命令。

联网搜索仍然只读；外部网页内容不能直接触发客户端写操作。社区发布、私信、广播等操作需要使用现有可信动作链和审计记录，不能把网页内容当用户命令。

## 10. 分期实施

### P0：说话不机械

- 先完成 `pet-emotion-runtime.js` / `pet-companion-p2.js` 到 `pet-particle-orb.js` 的表现适配，让现有情绪和行为真正可见。
- 将桌面形态拆为轻量 shell，主窗口保持唯一业务写入者；桌宠 ready 后才隐藏主窗口，初始化失败立即恢复主窗口。
- 建立统一 personality policy，动作执行和回复生成共用同一份情境快照。
- 消除重复开场、重复道歉和每次操作都确认的模板。
- 明确命令先执行；只有参数缺失且会产生多种不同结果时才追问。
- 每条主动消息记录触发原因、抑制原因和用户反馈，便于调试。

### P1：真正记得用户

- 接入 FE ID 长期记忆与账号隔离。
- 增加近期情境摘要和置信度，不把推断当事实。
- 实现用户可查看、修改、删除记忆的界面与命令。
- 让称呼、回复长度、玩笑接受度和夜间习惯稳定延续。

### P2：表达与音乐一致

- 粒子动作、语速、气泡时长与心情/精力联动。
- 主动机会评分替代随机定时消息。
- 周总结引用真实统计，并允许一键继续本周常听歌单。
- 加入失败恢复后的连续对话，而不是每次从“你好”重新开始。

## 11. 验收标准

- 100 次明确播放/切歌/参数命令中，不因人格状态拒绝执行。
- 同 FE ID 重启后称呼与明确偏好可恢复；不同 FE ID 之间零串号。
- 主动消息都能解释触发原因；免扰模式下主动消息为零。
- 相同主动意图和近似措辞七天内不重复。
- 执行动作的首个反馈不因人格层增加超过 50 ms 客户端延迟。
- 服务器离线时仍能完成本地播放控制，并准确区分“本地可用”和“联网不可用”。
- 所有状态机测试可注入固定时间与随机种子，深夜、回归、快切、离线恢复均有确定性回归测试。
